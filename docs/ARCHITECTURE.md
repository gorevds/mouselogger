# Архитектура

MouseLogger разбит на слои, связанные узкими интерфейсами. Это позволяет менять
способ захвата ввода и формат хранения независимо друг от друга и от логики
обработки.

## Поток данных

```
InputSource ──events──> Recorder ──events──> Sink ──> *.jsonl
 (захват)               (политика записи)    (хранение)
```

1. **InputSource** захватывает активность мыши и на каждое событие вызывает
   колбэк, передавая типизированный `Event`.
2. **Recorder** применяет сквозную политику: схлопывает повторы стационарного
   движения, но длинные простои фиксирует событием `IDLE` (сохранение пауз).
3. **Sink** пишет события на диск (JSONL, посуточная ротация, буферизация).

## Модули

| Модуль | Ответственность |
|--------|-----------------|
| `config.py` | конфигурация: пути, `participant_id`, частота, согласие |
| `event.py` | `Action` (enum) и `Event` (frozen dataclass) + сериализация |
| `session.py` | `SessionMeta` — метаданные сессии для лога и ML-пайплайна |
| `recorder.py` | дедуп с сохранением пауз, запись в `Sink` |
| `inputs/` | `InputSource` и бэкенды: `win_poll` (поллинг), `win_hook` (`WH_MOUSE_LL`) |
| `storage/` | `Sink`, `JsonlSink` (ротация), `archive` (zip) |
| `sysinfo.py` | ОС / разрешение / DPI для метаданных |
| `autostart.py` | автозапуск через реестр Windows (HKCU\\…\\Run) |
| `app.py` | сборка компонентов + остановка по сигналу |
| `cli.py` | команды `start/install/uninstall/status/purge`, гейт согласия |
| `export/` | сборка логов в таблицу признаков для обучения |

## Точки расширения

* **Новый способ захвата** — реализовать `inputs.base.InputSource` и
  зарегистрировать в фабрике `inputs.create_input_source`. Например, заменить
  поллинг на хук или добавить кросс-платформенный backend на `pynput`.
* **Новый формат хранения** — реализовать `storage.base.Sink`
  (CSV/Parquet/потоковая отправка) без изменения recorder и источников.
* **Новые признаки** — добавить вычисление в `export.features.extract_features`
  и колонку в `FEATURE_COLUMNS`.

## Кросс-платформенность и тесты

Windows-специфичные модули (`inputs/win_*`, `autostart`, win-ветки `sysinfo`)
не импортируются на этапе загрузки пакета: бэкенды грузятся лениво в фабрике,
а `winreg`/`ctypes.windll` — внутри функций. Поэтому платформонезависимое ядро
(config, модель данных, recorder, storage, export) полностью покрыто тестами и
проходит `ruff`/`mypy`/`pytest` на Linux CI. Поведение WinAPI-кода проверяется
на Windows.
