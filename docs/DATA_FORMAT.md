# Формат данных

Логи пишутся в формате **JSON Lines** (`.jsonl`): одна строка — один
JSON-объект. Файл назван `<participant_id>-<YYYY-MM-DD>.jsonl` и при пересечении
полуночи продолжается в файле следующего дня.

Текущая версия схемы: **2** (поле `schema` в мета-строке).

## Первая строка — метаданные сессии

```json
{"type": "meta", "schema": 2, "participant": "P-a1b2c3d4e5f6",
 "session": "9f1c…", "started_ms": 1733500000000, "os": "Windows-10-10.0.19045",
 "screen": [2560, 1440], "dpi": 96, "sample_hz": 50, "consent": true,
 "app_version": "0.2.0"}
```

| Поле          | Тип        | Описание |
|---------------|------------|----------|
| `type`        | строка     | всегда `"meta"` — отличает мета-строку от событий |
| `schema`      | целое      | версия формата лога |
| `participant` | строка     | псевдонимный идентификатор участника (не логин/PII) |
| `session`     | строка     | UUID сессии записи |
| `started_ms`  | целое      | время старта сессии, Unix-мс |
| `os`          | строка     | платформа (`platform.platform()`) |
| `screen`      | `[w, h]`   | разрешение основного экрана в пикселях |
| `dpi`         | целое      | горизонтальный DPI экрана |
| `sample_hz`   | целое      | частота опроса (для поллингового бэкенда) |
| `consent`     | булево     | факт согласия участника |
| `app_version` | строка     | версия MouseLogger |

Мета-строка дублируется в начале каждого посуточного файла, поэтому любой файл
самодостаточен. В пределах одной сессии `session` одинаков во всех файлах.

## Остальные строки — события

```json
{"a": "M",   "x": 412, "y": 771, "t": 1733500000020}
{"a": "L_D", "x": 412, "y": 771, "t": 1733500000180}
{"a": "S",   "x": 412, "y": 771, "t": 1733500000200, "v": -3}
{"a": "I",   "x": 412, "y": 771, "t": 1733500001000, "v": 800}
```

| Поле | Описание |
|------|----------|
| `a`  | тип события (таблица ниже) |
| `x`  | X-координата курсора, пиксели (знаковая: на мультимониторе бывает < 0) |
| `y`  | Y-координата курсора, пиксели |
| `t`  | время события, Unix-мс |
| `v`  | доп. величина: шаги колеса для `S`, длительность паузы (мс) для `I`; иначе отсутствует |

### Типы событий (`a`)

| Код   | Событие |
|-------|---------|
| `0`   | маркер начала сессии (резерв) |
| `M`   | перемещение курсора |
| `L_D` / `L_U` | нажатие / отпускание левой кнопки |
| `R_D` / `R_U` | нажатие / отпускание правой кнопки |
| `M_D` / `M_U` | нажатие / отпускание средней кнопки |
| `S`   | прокрутка колеса (величина и знак — в `v`) |
| `I`   | пауза/простой курсора (длительность мс — в `v`) |

## Замечания для анализа

* **Дедуп движения.** Подряд идущие `M` в одной точке не записываются. Простой
  дольше порога фиксируется отдельным событием `I` с длительностью — так
  сохраняется dwell-time (время «зависания» курсора).
* **Координаты — сырые, в пикселях.** Нормализацию в `[0, 1]` по `screen`
  выполняет экспортёр признаков (`mouselogger.export`), чтобы лог оставался без
  потерь, а признаки были сопоставимы между машинами.
* **Скролл** доступен только в хук-бэкенде; поллинговый его не фиксирует.
